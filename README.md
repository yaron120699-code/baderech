# בדרך.

**בדרך** הוא פרויקט שמחבר בין שלושה רבדים: תהליך הליווי עצמו, המתודולוגיה שמאחוריו, והמערכת שמאפשרת להפעיל ולפתח אותו לאורך זמן.

הריפו כולל את האתר הציבורי של בדרך, את ה־Playbook המקצועי, את Coach OS לניהול העבודה עם לקוחות, ואת שני כלי הכניסה: המבדק החינמי ובדיקת ההתאמה.

> המטרה של בדרך אינה לבנות דמות חדשה או ללמד טריקים. המטרה היא לעזור לאדם להביא יותר מעצמו לעולם, דרך הבנה, התנסות, פעולה ופידבק בחיים עצמם.

---

## מה יש בפרויקט

| אזור | נתיב | תפקיד |
|---|---|---|
| אתר ראשי | `/` | האתר הציבורי והצגת תהליך הליווי |
| Playbook | `/playbook/` | מסמך ההפעלה והמתודולוגיה של בדרך |
| Coach OS | `/coach/` | כלי עבודה פנימי לניהול תהליך, מיומנויות, Evidence והחלטות |
| מבדק | `/quiz/` | ״מפחד, או פשוט לא יודע?״ · מבדק חינמי עם ערכת שטח אישית |
| בדיקת התאמה | `/fit/` | שאלון קצר למי ששוקל להיכנס לתהליך |

האתר החי: **https://baderech.vercel.app/**

# 1. התהליך של בדרך

בדרך הוא תהליך אישי 1:1 לגברים שרוצים לפתח יותר נוכחות, ביטחון ושיקול דעת בעולם האמיתי.

דייטינג הוא אחת מזירות העבודה המרכזיות, משום שהוא חושף מהר מאוד פחד מדחייה, צורך באישור, תקשורת, גבולות, משיכה, הובלה וערך עצמי. עם זאת, המטרה של התהליך רחבה יותר מהצלחה עם נשים.

העבודה בנויה סביב ארבע תנועות בסיסיות:

1. **לראות**: להבין מה קורה עכשיו ומה מנהל אותי.
2. **לבחור**: להבין מה אני רוצה ומי אני רוצה להיות בתוך הסיטואציה.
3. **לפעול**: להפוך הבנה להתנסות אמיתית בעולם.
4. **להחזיק**: ללמוד להתמודד עם תגובה, אי־ודאות, הצלחה ודחייה בלי לאבד את עצמי.

המסגרת הנוכחית היא כ־**4 חודשים**, עם **8 מפגשי 1:1**, בדרך כלל בהפרש של כשבועיים. כל המפגשים קורים **בחוץ, בשטח** (מרחוק רק במצב חירום), ובסוף יש **מפגש תשיעי של סיכום בגוגל מיט**. מלווה אחד עובד עם **עד 3 מתלווים במקביל**.

התהליך עובר בחמישה שלבים: **מיפוי · זהות · נוכחות · התנסות · עצמאות**.

העבודה אינה מוגבלת לזמן המפגש. המשימות, החשיפות, ההתנסויות והפידבק שביניהם הם חלק מהותי מהתהליך.

המסגרת קבועה מספיק כדי לתת כיוון, אבל הקצב, העומק וסדר העבודה משתנים לפי האדם שנמצא בתהליך.

# 2. ה־Playbook

`/playbook/` הוא מסמך ההפעלה המקצועי של בדרך.

זה אינו דף שיווקי ולא סילבוס קשיח של שמונה שיעורים. הוא נועד לשמור את ה־DNA של השיטה, את עקרונות העבודה ואת צורת החשיבה שמאחורי החלטות בזמן אמת.

ה־Playbook כולל בין היתר:

- המצפן והעקרונות של בדרך.
- הגדרת האדם שמתאים לתהליך ומה עשוי לשבת מתחת לבקשה הראשונית שלו.
- המתודולוגיה: אבחון, תרגול, שטח, ניסוי ופידבק.
- מבנה התהליך והקשר בין מפגשים.
- כלי עבודה סביב נוכחות, סטייל, תקשורת, אפליקציות, דייטינג ואינטימיות.
- הגדרה של הצלחה ועצמאות.
- גבולות מקצועיים וסכנות אפשריות בתהליך.
- שיחת התאמה.
- מערכת למידה ושיפור של השיטה לאורך זמן.
- עקרונות תוכן וצמיחה של המותג.

### עיקרון חשוב

ה־Playbook הוא **ספר עיון**, לא מסילה שהלקוח חייב לעבור בה לפי סדר.

המטרה אינה לשאול "איזה פרק מגיע עכשיו?", אלא להבין מה צוואר הבקבוק הנוכחי, מה כבר נצפה בעולם האמיתי ומה ההתנסות הבאה שיכולה לייצר מידע או שינוי.

# 3. Coach OS

`/coach/` הוא כלי העבודה הפנימי של המאמן.

הוא נבנה כדי שהליווי לא יהפוך לאוסף זיכרונות, אינטואיציות והערות מפוזרות. המערכת מחברת בין האדם, מה שנצפה בפועל, ההשערה המקצועית והפעולה הבאה.

### המערכת כוללת

- **מפת מיומנויות**: מצב נוכחי של מיומנויות שונות על בסיס ראיות.
- **Routing / מה עושים עכשיו?**: שאלות שעוזרות לזהות את צוואר הבקבוק הבא.
- **Evidence**: תיעוד התנהגות ואירועים מהעולם האמיתי.
- **מבט לאחור**: רפלקציה משותפת עם הלקוח והשוואה בין חווייתו לבין נקודת המבט של המאמן.
- **Screening & Ethics**: שמירה על גבולות מקצועיים וזיהוי מקרים שבהם הליווי אינו המסגרת הנכונה.
- **מדדים**: מעקב אחרי הזדמנויות, ביצוע משימות והתקדמות.
- **עיון ב־Playbook**: גישה למתודולוגיה מתוך כלי העבודה עצמו.

### פילוסופיית העבודה של Coach OS

המערכת היא **Bottleneck first**.

במקום לסמן פגישה 1, 2, 3 ולהמשיך אוטומטית, מחפשים את הדבר שמגביל כרגע את ההתקדמות. העבודה נשענת ככל האפשר על Evidence ולא רק על תחושה או דיווח כללי.

סקאלת הביצוע המרכזית היא:

`נמנע → עם תמיכה → מבצע לבד → מכייל → עצמאי`

המטרה הסופית היא יותר עצמאות ופחות תלות במאמן.

### שמירת נתונים

Coach OS כרגע אינו מחובר לבסיס נתונים או לשרת.

- נתוני הלקוחות נשמרים ב־`localStorage` של הדפדפן.
- אפשר לייצא את המידע לקובץ JSON ולייבא אותו מחדש.
- מומלץ לבצע Export באופן קבוע כגיבוי.
- ניקוי נתוני הדפדפן עלול למחוק מידע שלא גובה.

# 4. האתר הציבורי

`index.html` הוא דף הבית של בדרך.

האתר נועד להסביר את התהליך בלי להפוך אותו למוצר מדף ובלי להבטיח תוצאה מהירה. הוא מציג את הסיפור, צורת העבודה, המסגרת, למי התהליך מתאים ומה הצעד הבא.

האתר כתוב בעברית מלאה וב־RTL, ומבוסס על HTML, CSS ו־JavaScript פשוטים.

אין framework, אין build step ואין מערכת CMS.

### עיצוב

השפה הוויזואלית היא **״יומן שטח״**: המחברת של מי שבאמת יוצא לבדוק.

- `Frank Ruhl Libre` לכותרות, `Heebo` לטקסט ולממשק, `Amatic SC` להערות קצרות בכתב יד.
- פלטה: נייר `#F7F6F1`, דיו `#1C1B18`, ירוק יער `#1F3D2B`, חול `#ECE8DD`, מרקר חימר `#EBCBB0`.
- שלושה סימנים: **מרקר** על משפט אחד חשוב, **מחיקה ותיקון** (סיפור ← עובדה), ו**כתב יד** של עד 6 מילים.
- מקסימום מרקר אחד ומחיקה אחת בכל מסך. רדיוס 2px, בלי גלולות.
- סגנונות דף הבית ב-`css/site.css`, בדיקת ההתאמה ב-`fit/fit.css`, והמבדק ב-`quiz/quiz.css`. `css/style.css` נשאר לדפים הפנימיים.
- בלי מקפים ארוכים (״—״) בשום טקסט.

# 5. המבדק `/quiz/`

״מפחד, או פשוט לא יודע?״ הוא המוצר החינמי של בדרך: מבדק של שלוש דקות שמראה לאדם מה תוקע אותו, ונותן לו ערך שאפשר לקחת.

- **שבע סיטואציות**, רובן עם נשים ושתיים לא (עבודה, חבר). סדר התשובות מתערבב בכל שאלה.
- **ארבעה דפוסים:** הפחד · הכלים · ההצגה · החשבון. הדפוס שחוזר הכי הרבה הוא התוצאה, ודפוס שני מוצג רק בתיקו.
- **ערכת שטח אישית לכל דפוס:** שיקוף, עובדה וסיפור, הטעות להפסיק, שיחה לדוגמה (היום מול עם הכלים), שלושה כלים, שבעה ימים בשטח עם סימון, שאלות תחקיר, ומשפט גשר לליווי.
- **שיתוף:** שמירת הערכה בוואטסאפ, העתקת התוצאה, ושליחה לחבר.
- התוצאה והימים שסומנו נשמרים ב־`localStorage`, כך שמי שחוזר רואה את הערכה שלו.
- הכפתור לבדיקת התאמה מוביל ל־`/fit?src=quiz`.

כל מבדק שהסתיים נשלח כשורה לגיליון נפרד, **״בדרך - מבדק״**, דרך Apps Script משלו. הקוד ב־`quiz/apps-script.gs`, והכתובת ב־`SUBMIT_ENDPOINT` בתוך `quiz/quiz.js`. העמודות והקישורים המומלצים מתועדים ב־`fit/SETUP-FIT.md`.

# 6. בדיקת התאמה `/fit/`

בדיקת ההתאמה היא מסלול קצר למי שכבר שוקל להיכנס לתהליך.

היא בנויה משבע שאלות ומחזירה תוצאה מיידית. המטרה אינה "לסגור" אדם אלא לבדוק האם הפורמט, הנכונות והציפיות שלו מתאימים למה שבדרך דורשת.

בסיום אפשר להמשיך לאתר, לפתוח שיחה בוואטסאפ, או לקבוע שיחה ביומן גוגל.

כשמגיעים למסך התוצאה, התשובות והתוצאה נשלחות כשורה אחת לגיליון Google Sheets ("בדרך - fit") דרך Google Apps Script. הכתובת מוגדרת ב־`SUBMIT_ENDPOINT` בראש `fit/fit.js`. הפרמטר `?src=` בכתובת נשמר בעמודה `source`, כדי לדעת מאיפה הגיעו. ההוראות המלאות, כולל עדכון הסקריפט, ב־`fit/SETUP-FIT.md`.

### מצב בדיקה

`?me=1` (בכל דף באתר) מסמן את הדפדפן כשל ירון: הביקורים לא נספרים ב־Vercel Analytics, ומילויים של המבדק ושל בדיקת ההתאמה נרשמים עם `source` שמתחיל ב־`test-`. מבטלים עם `?me=0`.

# 8. הרצה מקומית

מומלץ להריץ שרת מקומי משורש הריפו:

```bash
python3 -m http.server 8000
```

ואז:

```text
http://localhost:8000/           אתר ראשי
http://localhost:8000/playbook/  Playbook
http://localhost:8000/coach/     Coach OS
http://localhost:8000/quiz/      מבדק
http://localhost:8000/fit/       בדיקת התאמה
```

חלק מהדפים משתמשים בנתיבים שמתחילים ב־`/`, ולכן פתיחה ישירה דרך `file://` אינה דרך בדיקה אמינה.

# 9. Deploy

הפרויקט נפרס דרך **Vercel** ומחובר לריפו הזה.

כל push ל־`main` אמור להפעיל deployment חדש.

אין שלב build מיוחד. Vercel מגיש את הקבצים הסטטיים ישירות.

# 10. איפה נשמר מה

| מידע | מקום |
|---|---|
| החלטות מוצר, UX ותוכן | `DECISIONS.md` |
| המתודולוגיה המקצועית | `playbook/index.html` |
| נתוני לקוחות Coach OS | `localStorage` בדפדפן + Export JSON |
| מצב זמני של fit | `sessionStorage` |
| מילויי בדיקת התאמה | גיליון ״בדרך - fit״ |
| מבדקים שהסתיימו | גיליון ״בדרך - מבדק״ |
| התוצאה של המבדק בדפדפן | `localStorage` |
| כניסות לדפים | Vercel Analytics |
| קוד האתר | הריפו הזה |

### חומרים מחוץ לריפו

חלק מהחומרים של בדרך הם קבצים ולא חלק מהאתר:

- **CORE:** חוברת העבודה של המתלווה, PDF של 64 עמודים. היא ניתנת רק בתוך הליווי.
- **דף ליווי:** שני עמודים למתלווה, ניתן במפגש הראשון.
- **מדריך המלווה:** מסמך פנימי, מה קורה בכל אחד מתשעת המפגשים.
- **מחשבות יתר:** הפודקאסט של ירון, ״פודקאסט מבית בדרך״, בספוטיפיי.

`DECISIONS.md` הוא יומן ההיסטוריה של הפרויקט. לפני שינוי גדול באתר או בזרימה, כדאי לבדוק מה כבר הוחלט ולמה.

# 11. עקרונות לפיתוח עתידי

כשמוסיפים פיצ'ר או תוכן חדש, הוא אמור לשרת לפחות אחד מהדברים הבאים:

- לעזור לאדם להבין את עצמו טוב יותר.
- להפוך הבנה להתנסות בעולם האמיתי.
- לעזור למאמן לקבל החלטה טובה יותר.
- לצמצם תלות ולהגדיל עצמאות.
- לשפר את יכולת הלמידה של השיטה מתוך מה שקורה בפועל.

אם משהו רק מוסיף מורכבות, נראה מרשים או מייצר עוד מסך בלי לשפר אף אחד מהדברים האלה, כנראה שלא צריך אותו עדיין.

## סטטוס

הפרויקט נמצא בפיתוח פעיל. המתודולוגיה, האתר וכלי המאמן ממשיכים להשתנות מתוך עבודה אמיתית עם אנשים, תיעוד, ניסוי ולמידה.

**בדרך היא לא מערכת שסיימנו לבנות. גם היא בדרך.**
